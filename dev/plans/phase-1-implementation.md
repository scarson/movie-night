**Deferred to Phase 2:** Vectorize, embeddings, Taste Autopsy, tension axes, TV show seed.

## Architecture Decisions (from eng review)

- **Invite codes:** 8-char nanoid, no expiry, reusable. Rate-limited join endpoint.
- **Loading UX:** Phased client-side text transitions during 5-15s Claude API wait.
- **Rate limiting:** D1-based (round_number in recommendations table). Max 10 rounds/session. Monthly cap via COUNT query. Simple SELECT check (theoretical race condition accepted — blast radius is $0.04).
- **Staleness tracking:** `last_refreshed_at` on titles table. Show "as of [date]" on streaming badges >14 days old.
- **JSON columns:** Keep for flexible data (profiles, genres, streaming). D1 generated columns as escape hatch if SQL filtering needed later.
- **Prompt builder:** Single `buildMatchingPrompt()` with mode params (initial/refinement). Solo detected from member count.
- **Title resolution:** Pass `tmdb_id` in candidate list, require Claude to return `tmdb_id` per recommendation. Validate IDs against D1.
- **Matching tests:** Full seam tests (prompt construction, response parsing, error handling) + live eval suite with real Claude API calls (behind env flag in CI).
- **Observability:** Workers Logs + Tracing enabled day 1 in wrangler.jsonc. Structured JSON logging built into matching endpoint. Grafana pipeline deferred.
- **Product rules:** Invite codes don't expire and are reusable. Sessions include all group members. Members can leave groups; history preserved. Account deletion anonymizes shared records.
- **Anthropic 429 handling:** Distinct error branch in matching endpoint. User-facing message: "We're getting a lot of requests right now, try again in a moment."

## Build Order

### Step 0: Response Types + Project Setup
- Define matching response JSON schema as TypeScript types in `src/types/`
  - TasteMap, Recommendation, ConversationalView, MatchingResponse
- Initialize Next.js project, configure OpenNext, wrangler.jsonc (with observability enabled), tsconfig, vitest, eslint
- Reuse project configuration patterns from twin-cities-tee-times

### Step 1: D1 Schema
- `migrations/0001_initial_schema.sql` — all tables including Phase 2 tables (empty)
- Tables: users, profiles, groups, group_members, movie_sessions, session_members, recommendations, titles
- Phase 2 tables (created empty): watch_history, watch_ratings, tension_axes
- `titles.last_refreshed_at` column for staleness tracking
- `src/lib/db.ts` — D1 utilities, sqliteIsoNow()
- `src/types/` — D1 row types

### Step 2: Auth
- Port Google OAuth from twin-cities-tee-times (arctic + jose)
- `src/lib/auth.ts` — authenticateRequest(), session management
- `src/app/api/auth/` — google, google/callback, logout, me routes
- Cookie-based sessions with `mn-` prefix (movie-night, not tct-)
- `env.d.ts` — Cloudflare bindings (GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, JWT_SECRET, DB)

### Step 3: TMDB Integration (parallelizable with Step 2)
- `src/lib/tmdb.ts` — TMDB API client (search, popular, top-rated, now-playing, watch-providers)
- `scripts/seed.ts` — seed script fetching thousands of movies via paginated endpoints. Filter: 50+ votes. Write to D1 incrementally (not all in memory).
- `src/lib/cron-handler.ts` — weekly streaming availability refresh. Log success/error counts. Update `last_refreshed_at`.
- `worker.ts` — scheduled() handler for cron

### Step 4: Group Linkage
- `src/app/api/groups/` — create (generates 8-char nanoid invite code), join (validates code + rate limit), get (members)
- Group membership CRUD in `src/lib/db.ts`

### Step 5: API Routes + Matching Engine
- `src/app/api/user/profile` — GET/PUT profile CRUD
- `src/app/api/sessions/` — create session
- `src/app/api/sessions/[id]/match` — matching endpoint
- `src/app/api/sessions/[id]/refine` — refinement endpoint
- `src/app/api/titles/search` — TMDB search for profile comfort movies
- `src/lib/matching.ts` — buildMatchingPrompt() + callClaude() + parseMatchingResponse()
  - Candidate list includes tmdb_id. Prompt requires Claude to return tmdb_id per recommendation.
  - D1-based rate limiting (round_number check before Claude call)
  - Input sanitization (max lengths on all text fields)
  - Output validation (JSON parse, schema check, tmdb_id validation against D1)
  - Structured JSON logging (event, group_id, session_id, claude_latency_ms, tokens_in, tokens_out, response_valid, model)
  - Distinct error handling: malformed JSON (retry once), timeout (graceful error), Anthropic 429 (specific message)
- Auth middleware on all protected routes

### Step 6: UI
- Build from scratch using `frontend-design` skill + `DESIGN.md`
- Use `mockup.jsx` as functional spec (screen flow, data shapes) NOT visual starting point
- Components: ProfileScreen, MoodScreen, ResultsScreen (TasteMap, RankedList, ConversationalView tabs)
- Quick-match flow: group → mood tags → match → results
- Full ritual flow: edit profiles → mood → match → results → refine
- Solo mode: "Just me tonight" option, group of 1
- Phased loading UX (timed text transitions: "Reading your tastes...", "Finding the overlap...")
- Rough-day toggle: private, heart icon, amber fill. Never visible to partner.
- Safe rendering: no dangerouslySetInnerHTML. Use DOMPurify or safe markdown renderer for AI text.
- 44px touch targets, 16px+ input font sizes, ARIA landmarks

### Step 7: Posters + Landing Page + Privacy Policy
- TMDB poster images on recommendation cards (poster_url from titles table)
- Landing page for unauthenticated users (product explanation, taste map example, CTA)
- Privacy policy page (human-readable, linked from landing page)

### Step 8: Deploy
- GitHub Actions CI: type-check, lint, test, build (parallel jobs)
- OpenNext build → wrangler deploy to movienight.scarson.io
- D1 migration applied to production
