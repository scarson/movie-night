# 1.4.10 Reflow — 400% zoom equivalent (320 CSS px) verification

**Date:** 2026-08-01
**Criterion:** WCAG 2.2 SC 1.4.10 Reflow — content and functionality must remain available,
with no loss of information or functionality, and without requiring scrolling in two
dimensions, at a viewport of 320 CSS px width (the standard equivalent of 400% zoom on a
1280px-wide reference design), except for content where 2-D layout is essential (data
tables, maps, images, video, etc.).

## Methodology

- **Server:** `npx next dev -p 3010` run directly from
  `/Users/sam/Code/movie-night/.claude/worktrees/a11y-verification` (no Cloudflare bindings).
  `getCloudflareContext()` is unavailable in this mode, so every call to `/api/auth/me`
  returns **500 Internal Server Error**. The client auth hook (`src/components/auth-provider.tsx`)
  treats any non-OK response as "not signed in" (`res.ok ? ... : null`), so this reproduces
  the real signed-out experience faithfully — it is not a broken test, it's the correct
  signed-out code path exercised via a different trigger than a real session cookie.
- **Browser:** Claude Browser pane (Chromium), viewport resized to **320×800**, no
  device-pixel-ratio/zoom trick needed since 320px *is* the target CSS viewport per the
  1.4.10 400%-zoom-at-1280px-reference convention documented in accessibility.md.
- **Overflow detection:** for every route, ran a JS probe comparing
  `document.scrollingElement.scrollWidth` vs `clientWidth`/`window.innerWidth`, and walked
  every element in `body *` computing `getBoundingClientRect()` to flag any element whose
  right edge exceeds the viewport width (with computed `width`, `min-width`, `white-space`
  attached for diagnosis). This is scroll-position-independent (horizontal position isn't
  affected by vertical scroll), so a single pass covers the full page height for horizontal
  overflow; vertical scrolling + screenshots were used additionally to visually confirm no
  clipped/overlapping content, per the instruction that screenshots are a hint, not evidence.
- **Limitation:** this run could not exercise any authenticated screen. See Coverage gaps.

## Interactive states exercised

- Landing page: full-height scroll, both signed-out CTAs visible ("Sign in" nav link,
  "Sign in with Google" hero button) — no interaction possible past that without real OAuth.
- `/groups/join/[code]`: signed-out branch only (invite code display + "Sign in with Google").
- Genre-chip grid, mood-tag chips, results tabs, taste-map — **all live behind auth** (in
  `/quick`, `/ritual`, `/tonight`, `/results/[sessionId]`) and were not reachable in this
  session. Not exercised.
- Nav's signed-in avatar/dropdown menu — not reachable (nav only renders the signed-out
  "Sign in" link when `user` is null).

## Coverage gaps

- **No authenticated page state was tested.** `/quick`, `/ritual`, `/tonight`, `/profile`,
  `/groups`, and `/results/[sessionId]` all short-circuit to `null` and then
  `router.replace("/")` before any of their real layout renders, because `next dev` has no
  Cloudflare bindings and `/api/auth/me` always 500s. This is exactly the limitation flagged
  in the task setup, not a new finding. These pages contain the app's most layout-dense
  UI — the genre/mood chip grid, the results tabs, the taste-map — and per accessibility.md
  the chip grid ("~18 outlined pills at once") was previously flagged as a density risk
  worth checking. **None of that density was checked at 320px in this pass.** Verifying it
  needs either a real signed-in session against the deployed/preview app, or a
  Cloudflare-bindings-aware dev mode (`npm run preview` / wrangler dev with a seeded D1 and
  a valid session cookie).
- **`/groups/join/[code]`'s signed-in branch** ("Joining adds you to the group…" + "Join
  this group" button) was not reachable for the same reason.
- No 2-D-layout content (data tables, maps) exists on any page tested, so the 1.4.10
  exception clause never came into play — not applicable here, not a gap.

## Overall verdict

**1.4.10 Reflow: PASS for every route state that could be rendered in this session** —
`/`, `/privacy`, and the signed-out branch of `/groups/join/[code]` all reflow cleanly at
320px CSS width with zero horizontal overflow and no observed content or functionality loss.

**This is not a full-app verdict.** The six auth-gated routes could not be tested past their
redirect in `next dev` mode, so the app's most layout-dense screens (chip grids, results
tabs, taste-map) remain **unverified** at 400%-zoom-equivalent width. The
`docs/accessibility.md` "Not yet verified" entry for 1.4.10 should be updated to reflect
partial verification (signed-out surfaces confirmed passing) rather than closed outright —
the authenticated screens need a follow-up pass with a real or seeded session, ideally
against `npm run preview` (wrangler dev, which does have Cloudflare bindings) or the
deployed app.
