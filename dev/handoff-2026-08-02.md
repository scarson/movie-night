## The first deploy will fail — three known reasons

`npm run preflight -- --remote` was run against the real Cloudflare account and database (PR #39):

1. **Migrations `0002`, `0003`, `0004` are unapplied.** `0002` is the dangerous one —
   `authenticateRequest` runs ahead of every route's error handling, so signed-in users would hit raw
   500s. Commands are in `docs/deploy.md` §Pending migrations, in numeric order.
2. **`titles` is empty.** The app is unusable with no catalog; seeding needs `TMDB_API_TOKEN`.
3. **The Worker does not exist on the account yet**, so no secret is set.

Run the preflight before anything else on deploy day. It derives migration expectations from the DDL
itself — including reading a `DROP INDEX` as an *absent* expectation, which is the only way an
unapplied `0004` is detectable.

## Not started, and nobody owns them

Small things surfaced by agents that correctly stayed in scope. None is urgent; all are real.

- **Group size is uncapped**, so prompt size and attacker-controlled text volume are unbounded. Fix
  belongs in `src/app/api/groups/join/route.ts`. Raised by the injection work.
- **`seed-lib.ts`'s `INSERT OR REPLACE` also resets `created_at`**, rewriting the catalog's creation
  history on every re-seed. Nothing reads that column today.
- **`npm test -- <file>` runs the whole suite** — `--pass-with-no-tests` swallows the positional. Every
  group depends on that script, so nobody changed it.
- **`createFakeD1().batch()` silently runs statements prepared from a *different* fake** against the
  wrong database. Only the `withFailingStatement` wrapper guards it.
- **D1's own migrations system is bypassed.** `wrangler.jsonc` sets no `migrations_dir`, so it defaults
  to `migrations/` — anyone running `wrangler d1 migrations apply --remote` will find `0001` "unapplied"
  and try to re-run it, and `0001` has no `IF NOT EXISTS`. Hand-applied SQL is a deliberate project
  choice; the collision is undocumented outside this line and `docs/deploy.md`.
- **Match-route round-trip budget is 10, not 8.** Folding the match count into `getMatchRoundContext`'s
  batch would recover two, but `movie-sessions.ts` belonged to another agent at the time. The budget
  test was updated to 10 with the reason written in, not silently loosened.

### Two traps for anyone porting the provider call

Both measured during the spikes, both would bite a rewrite of `callClaude`:

- **`parseMatchingResponse` throws** a `MatchingError` rather than returning a result kind. Two separate
  harnesses assumed the latter and had to be corrected.
- **Reasoning models return the answer in `message.reasoning` with `content: null`.** A script that read
  only `content` scored a model 0/8 that had in fact answered correctly every time. A naive port would
  mark every such reply `malformed`.

And one argument for keeping defence in depth: a `glm-4.7-flash` sample returned **both an explicitly
excluded title and a dealbreaker-genre title, and both passed the parser** (the ids were valid).
Production is saved only by `selectCandidates`' SQL pre-filters — which makes the Cloudflare spike's
suggestion of relaxing those to a prompt instruction plus post-filter measurably risky.

## Seams — where two pieces of work met

These are the places a fresh agent reading one artifact would get a wrong impression.

- **The flaky-test fix was replaced, not extended.** PR #22 raised a test's timeout 20s → 60s and wrote
  "inherently heavy… 12s to 24s" into a code comment. PR #27 later *measured* it: 2.67s, stretched ~8x
  by concurrent load, with the real cost a per-click `getByRole` re-scan. It now runs ~950ms with a 10s
  budget. **#22's log entry alone would mislead you.**
- **PR #31 carried a bug forward verbatim.** When it collapsed the match route's reads into one
  `db.batch`, it moved the unguarded `getRecommendedTmdbIds` loop unchanged. PR #32 found and fixed the
  resulting live 500. So the batching PR is not the origin of that guard, and the guard is not part of
  the batching design.
- **PREP rebased before merging**, so G2 and G4 — stacked on its pre-rebase SHAs — needed
  `git rebase --onto origin/dev <old-tip>` rather than a plain rebase. If any future work stacks on an
  unmerged branch, expect this.
- **Ownership boundaries were crossed deliberately, twice.** Tier-2 found `MAX_SESSIONS` was not in
  `auth.ts` at all but inline in the OAuth callback — a file on its do-not-touch list — and moved it to
  make it testable. G6 rewrote five pre-existing 1.4.11 assertions its brief didn't grant it. Both are
  disclosed in their PR bodies; neither is a rule the next agent should assume they inherit.
- **`prompt_version` is hardcoded in two test files.** The injection work bumped `p1.1` → `p1.2` and had
  to edit `movie-sessions.test.ts` and the match route test outside its ownership. Any future
  `PROMPT_VERSION` bump must do the same.
- **The effort sweep measures ordering on raw model output**, deliberately, because PR #43 now makes
  `parseMatchingResponse` sort. Do not "fix" that scorer to use the parser — it would read 0 for every
  cell and stop measuring model behaviour.
- **`docs/deploy.md`'s "Pending migrations" section was authored by the wrong group.** The plan assigned
  it to G1; G1 had not started, so G7 created it to have somewhere to put `0004`, and G4 then appended
  `0003`. It reads as one coherent section now, but its structure was improvised across three PRs — the
  numeric ordering is maintained by hand, not by anything that enforces it.
- **The e2e smoke report carries a scope caveat that has since been closed.** It measured against
  `a60483f`, and PRs #29/#30/#31 landed afterwards. PR #33 re-verified all three against a running
  Worker and found no defects. Read the caveat in that report as **historical** — it is answered in
  PR #33's follow-up section appended to the same file.

## Guardrails accumulated this session

Everything in `dev/handoff-2026-07-28.md` §Operational guardrails still holds (jsdom has no layout or
CSS cascade; Tailwind resolves by stylesheet order; composite alpha before comparing contrast;
`:focus` needs OS window focus; `next dev` has no Cloudflare bindings). New, and now also written into
`docs/pitfalls/` where they generalise:

**Process**
- **`dev/implementation-log.md` merges with `union`** (`.gitattributes`) — parallel branches all append
  to it. Do not "fix" that setting. Note **GitHub does not apply the union driver**, so it still reports
  the file as conflicting even when `git merge-tree` merges cleanly; rebase locally.
- **GitHub intermittently fails to dispatch CI on PR open.** Close/reopen does **not** re-trigger it;
  only a push creating new commits does. Seen on at least four PRs. Never merge on local gates alone
  without saying so — and I merged PR #35 on pending checks once, which passed but was luck, not process.
- **zsh arrays are 1-indexed.** A `sed` built from `${M[0]}` expanded to a bare `d` and deleted every
  line of the implementation log mid-rebase (recovered with `git checkout --merge`). Never build a
  destructive command from an unvalidated array index.
- **A backgrounded `&` loop plus a `sleep` wrapper kills its own children** when the parent exits. The
  wrapper must `wait`.
- **Model availability via the local `codex` CLI is narrower than the model list suggests.** `gpt-5.6`
  is rejected outright on a ChatGPT account (`invalid_request_error`); `gpt-5.6-sol`, `-terra` and
  `-luna` all work. Effort levels are `none|low|medium|high|xhigh|max` — `minimal` is rejected. Probe
  before building an arm around a model id.

**Testing**
- **PREP's failure-injection helper fails silently in three ways** — a typo in `match`, an `onCall`
  overshoot, or building the wrapper after the route's db mock. The natural assertions are true on the
  happy path too. **Assert `injectedFailureCount(db)` in every interrupted-success test.**
- **The synchronous fake D1 cannot prove concurrency.** Several agents wanted to; none did. Say what a
  test proves and what it cannot rather than writing a `Promise.all` costume.
- Four new §7 entries in `docs/pitfalls/testing-pitfalls.md` cover comparison-arm fairness, treating a
  0/N result as a harness hypothesis, measuring before raising a timeout, and prompt-cache-poisoned
  token counts.

**Platform**
- New **PLAT-3** in `docs/pitfalls/implementation-pitfalls.md`: D1 refuses `pragma_*` table-valued
  functions joined across every table with `SQLITE_AUTH`, while working fine filtered to one — so the
  first spike looks correct and the generalised version fails only against real D1.
- **Workers Paid is confirmed** for this account and is a prerequisite; Free's 10 ms CPU makes the app
  non-viable regardless of `STALE_TITLES_LIMIT`. Verified: Paid allows **10,000** subrequests per
  invocation (the 1,000 figure was removed 2026-02-11) — that stale number sent two independent
  reviewers to opposite conclusions.

## The lesson worth carrying

**A class of plan defect survives adversarial plan review and is caught only when an implementer runs
the prescribed test, or a reviewer checks a justification against reality.** Every one of the eight
remediation groups hit at least one:

- tests the plan prescribed that **could not fail** before the fix (G2, G3, G4, G5, G6, G1)
- an **inverted technical justification** — `crossOrigin=""` on a preconnect "because posters are
  anonymous-CORS"; they are no-CORS, so it warmed a pool the images can never reuse
- a rationale resting on an **unchecked UI default** — "make the LCP element eager" for an element that
  is not in the DOM at first paint, because its tab defaults closed
- a migration **citing an audit that recommended the opposite**

In each case *the code was fine and the justification was wrong* — the version that ossifies in a
comment and outlives everyone who could question it. Budget for implementer pushback, and instruct
subagents to **report** plan defects rather than either silently complying or silently "fixing".

**What did work, upstream of that:** a two-reviewer sanity panel run against the remediation decisions
*before* any code was written overturned six of them — including dropping a pool floor that could never
fire, expanding the prompt-sanitisation scope from synopsis text to every user-controlled field, and
catching that a privacy fix would itself leak through the *absence* of a UI element. The reasoning for
each is in `dev/research/2026-08-01-remediation-decisions.md`. The panel also demonstrated its own
limit: both reviewers argued a decision from the same stale platform figure and reached opposite
conclusions, which only checking the primary source resolved.
