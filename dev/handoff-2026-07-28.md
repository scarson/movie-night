### PR #5 — WCAG 2.2 AA remediation (the three open gaps)

| Gap | Fix | Measured |
|---|---|---|
| **1.4.11** | Resting borders on interactive controls `slate` → `ash`; `slate` kept for dividers, panel edges, hover washes, disabled controls (exempt as inactive components) | 1.53:1 / 1.34:1 → **6.21:1 / 5.44:1** |
| **2.4.2** | Server `layout.tsx` per client segment + root title template | All 9 routes distinct |
| **2.4.1** | `SkipLink` first in `<body>`, `id="main" tabIndex={-1}` on all 20 `<main>` branches | 44px target, amber ring |

**Three defects survived a green 561-test suite and were caught only in a real browser.** This
is the single most important lesson to carry forward:

1. **The skip link moved nothing.** A bare `<main id="main">` is not focusable, so activating it
   scrolled while `activeElement` stayed on `<body>` — the next Tab returned to the banner the
   user had just asked to skip. It looked correct and did nothing.
2. **The focused skip link had zero padding.** Tailwind's `not-sr-only` resets `padding`, so the
   unprefixed `px-md` lost the cascade.
3. **A fourth 1.4.11 gap the audit had missed:** `ToggleRow`'s switch track. Knob position is the
   only visual carrier of on/off, and the off state was 1.34:1 track / 1.53:1 knob — invisible to
   a `border-slate` grep because it is a `bg-` utility.

Also found a **seventh** untitled page (`groups/join/[code]`) beyond the six documented.

### PR #6 — outlined control classes extracted

`src/components/control-classes.ts`. The design call worth remembering: the first cut bundled
`rounded-control` into the shared constant, and the new anti-duplication guard immediately failed
on `chip.tsx` and `group-picker.tsx` (which are `rounded-pill` / `rounded-panel`).
**Bundling shape — a per-control design choice — with the boundary — a conformance requirement —
is what created the duplication in the first place.** Split into `outlinedBoundaryClasses`
(border + hover, no radius) and `outlinedControlClasses`. Real count was eight sites, not five.

Class strings rather than a `<Button>` component, because call sites mix `<button>` and `<Link>`
and several append modifiers; a component would need polymorphism plus class merging.

## Operational guardrails — don't rediscover these

**Verification**
- `next dev` has **no Cloudflare bindings**; `/api/auth/*` throws a `getCloudflareContext` error
  under it. That error is expected and unrelated to whatever you are changing. For anything
  binding-dependent use `npx wrangler dev` after an OpenNext build. For pure presentation and
  metadata work `next dev` is fine and much faster.
- **jsdom has no layout, no CSS cascade, and no fragment-navigation focus.** This is now the
  third session in a row where that produced a false green. Anything about focus movement,
  painted color, or size needs a real browser.
- **Composite alpha before comparing contrast.** `--amber-glow` is `#e8a84920`; comparing against
  a raw translucent background gives nonsense (an amber track measured "1.00:1"). Walk the tree
  and composite to a solid first.
- **`:focus` does not match when the browser window lacks OS focus,** even though
  `document.activeElement` is set. A programmatic `.focus()` in a background pane looks exactly
  like broken CSS. Check `document.hasFocus()`, or drive it with a real Tab keypress.
- **The Browser pane's screenshot can lag the DOM.** Measure with `getComputedStyle` /
  `getBoundingClientRect`; treat a screenshot as a hint, not evidence.
- Two synthetic `.click()` calls in one JS block both read pre-click props (React batches within
  a task). `await` between them.

**Tailwind**
- Conflicting utilities resolve by **stylesheet order, not class-attribute order**. Appending
  `px-lg` to a string that already contains `px-md` is undefined behavior. Compose from a base
  that omits the conflicting axis instead. There is no `tailwind-merge` in this project.
- `sr-only` / `not-sr-only` reset `padding`, `position` and sizing. Any layout utility that must
  survive the swap has to be `focus:`-prefixed.

**Next.js metadata**
- A `title.template` applies **only to a segment's children**, and a plain-string title passes
  none further down. Any segment with route segments beneath it must restate the template — see
  `src/app/title-template.ts`.

**Testing**
- jsdom has **no working `localStorage`** in this setup. Inject a store or `Object.defineProperty`.
- Each `PhasedLoading` phase's timer is scheduled by the effect after the previous render, so
  advance one phase at a time.
- Turbopack/SWC drops the leading space in some JSXText continuations after a closing tag while
  esbuild preserves it — vitest stays green while the served HTML is wrong. Use explicit
  `{" — "}` for load-bearing whitespace.
- Some heavy jsdom tests sit near vitest's 5s default and time out on CI's slower runner. Set an
  explicit generous timeout rather than trimming the assertion.

**Accepted, do not re-litigate**
- Two check-then-act TOCTOU races (group-join rate limit, match round limit) are **deliberately
  accepted**, reasoned twice in the plan and log. The fake D1 is synchronous and cannot reproduce
  them anyway.
- **`ember` must never carry normal-size text on `charcoal`** (4.12:1). It is only ever used on
  `midnight` (4.70:1).
- **`slate` is never a control boundary.** Dividers, panel edges, hover washes, disabled controls
  only. `ash` is the resting boundary for anything interactive.

## The one judgment call worth a second opinion

Raising every interactive border from `slate` to `ash` is a real visual change to the app's
calmest surfaces. I checked it at 375px and 1280px and it reads as a calm outlined set rather
than a shout — amber still owns selected and primary, and kept-slate dividers stay visibly
fainter than control boundaries, which is the distinction the rule draws. The densest surface
(the ~18-pill genre grid) is the one to look at.

But it is a design judgment made by an agent against a deliberately quiet brief. If Sam thinks
it is too loud, the documented fallback is a dedicated mid-tone token between `slate` and `ash`
that still clears 3:1 — and because the boundary now lives in one constant, that change is a
one-line edit.
